# 演示视频维护指南

README 的展示顺序是：先看成片，再了解用途和原理，最后进入安装与开发文档。目前已放入五段配乐前半段成片：原始 M4A、红色高跟鞋、回马枪、梦的翅膀受了伤、一笑江湖。

另在 README 顶部加入工作台操作与成片合集（约 2 分 48 秒、720p、约 20 MB），配套四张原始 1080p 截图。视频展示选择工程、延长音轨、补齐后续、局部换镜和导出；部分等待已加速。详见 [工作台操作](WORKBENCH.md)。视频和截图信息统一记录在 `showcase.json` 的 `workbenchDemo` 中。

本批视频压缩为轻量展示版，总计约 13 MB，保留原始 960×540 画幅、时长与剪辑，通过 [Release 附件](https://github.com/chenbaiyujason/jev-cut/releases/tag/showcase-2026-09-27) 提供；README 使用真实成片封面链接到 MP4，浏览器可能播放或下载。各版本的时长、主题、文件哈希与链接记录在 [showcase.json](showcase.json)。本机工作台菜单已由制作流程替换成对应五个工程，发布仓库不复制依赖本机素材库的工程文件。

## 回传什么

直接提供 **16:9 视频文件**即可。推荐 1920×1080 或 1280×720 的 MP4，使用 H.264 视频与 AAC 音频；保留原有帧率，不为凑规格拉伸、裁掉画面或插帧。

如果方便，随视频附上以下信息；缺少的信息可在接入时从项目记录或文件中补齐，不能猜测：

| 信息 | 用途 |
|---|---|
| 短标题 | 帮读者快速理解这段演示 |
| 使用的音乐与区间 | 区分不同音乐输入，说明实际剪辑长度 |
| 实际剪辑目标 | 对应人物、主题或情感输入；空提示词如实标注 |
| 项目版本与模型 | 便于复现与对比，保留实际模型名称 |
| 人工修改情况 | 区分直接生成结果与后续人工调整的成片 |
| 希望做封面的时间点（可选） | 未指定时从成片挑选清楚、能代表效果的一帧 |

如果需要演示速度，分别记录素材预处理、从输入到时间轴完成、成片渲染的用时，并注明缓存情况。不要用加速录屏或仅渲染用时代替决策耗时。

## 两个展示位

- **主展示**：选最能代表当前剪辑质量的一段完整成片，放在 README 最上方。
- **对比展示**：同一套素材更换音乐或主题。多段成片以两列封面展示，各自提供完整 MP4 链接，播放时保留原画幅。

README 中用以下注释标记替换范围，保留标记，替换内部的占位文字：

```text
<!-- showcase:main:start -->
主展示内容
<!-- showcase:main:end -->

<!-- showcase:comparison:start -->
对比展示内容
<!-- showcase:comparison:end -->
```

## 如何接入视频

成片不直接加入 Git 历史。上传可用于展示的版本后，在 README 引用视频地址；封面可以保存到 `docs/assets/showcase/`，收到真实成片后再创建对应图片。

GitHub 支持在 Markdown 编辑界面附加文件，并生成附件 URL，操作见 [GitHub 官方附件说明](https://docs.github.com/zh/get-started/writing-on-github/working-with-advanced-formatting/attaching-files)。拿到视频附件地址后，放入展示位，在仓库实际渲染页验证播放效果；不要将本机路径或仓库中一个 `.mp4` 相对路径当作已经可播放的嵌入视频。

使用其他托管地址，或者内嵌播放不可用时，采用“16:9 封面 + 点击观看”的形式。以下是维护模板，只有真实地址与封面到位后才复制到 README：

```markdown
[![演示标题：点击观看](docs/assets/showcase/main.jpg)](替换为真实视频地址)

**输入**：实际剪辑目标 · **音乐**：名称与区间 · **时长**：实际时长

**版本**：提交或版本号 · **模型**：实际模型名称 · **人工调整**：如实说明
```

这段图片路径以仓库根目录的 README 为基准。视频地址应允许目标读者访问；公开展示前检查附件或托管地址的实际访问权限，不能仅凭仓库是否私有判断媒体可见性。

## 更新后检查

1. 在 GitHub 的 README 页面打开视频，检查画幅、播放、声音和封面。
2. 核对视频对应的输入、音乐、版本和人工调整说明；移除该展示位的“待上传”文字。
3. 核对没有加入本机路径、配置、凭据、原片或未经选定的工作截图。
4. 运行 `npm run audit`，只提交本次 README、指南和选定封面的变更。

README 与本指南属于发布仓库自有文档，不受源码快照同步覆盖。原开发目录可以继续更新，视频展示也可以独立更新；具体规则见 [并行开发与发布](DEVELOPMENT.md)。
