# 候选选择与缓存

当前主入口为 `apps/backend/global-director.mjs`，策略版本 `jev-wide-fast-v2`。运行中的后端通过 `GET /api/studio/generation/capabilities` 的 `candidatePolicy` 字段报告策略版本。

## RAG 与 jev 各做什么

每次决策从完整可搜索素材库召回，重试预算依次为 96、192、384。来源范围、执行边界、明确叙事约束及默认复用保护仍会筛除不合格项；其余候选全部进入 jev 基础评分，不再固定从96个压到16个。

送入模型前按上下文与镜头 ID 做确定性打散。RAG 排名既不作为最终适配分，也不作为模型同分时的偏好。各候选作为独立问题，共享主题和当前乐段上下文。请求按估算 token 预算与问题数量分组；服务端若报告上下文超限，可继续拆分。

基础评分后，按模型分数准备六个镜头的合法窗口，先保证不同镜头各有选项，再补充长短版本。最终一次 choice 结合前后镜、重音、使用记录和实际窗口选择镜头与结束点，也可以要求继续寻找。

## 为什么缓存不会锁死后面的剪辑

基础评分回答的是“这份素材适不适合当前主题和乐段”，缓存键包含策略、模型、主题、提示词、乐段、素材描述／对白／动作以及明确角色阶段。

前镜变化、已有使用记录和精确切点不属于这个基础评分问题，它们每次都进入最终窗口选择。最终选择本身不缓存，因此缓存命中不等于沿用上一镜的答案。改变主题、乐段或素材事实会使对应基础评分失效。缓存文件通过临时文件原子替换，避免并发读到半份 JSON。

## 重复与动作延续

默认不把已用镜头重新放入普通替换名单；`repriseAllowed` 或 `intentionalReuse` 显式标记可允许有意重复。连续动作另有使用新源帧的续接选项。

窗口编译仍检查已使用源帧，模型还会看到 `usage.replayedFraction` 和 `previousWindowOverlap`。这些值区分已经播放的原帧、紧邻前镜重叠和真正的后续动作。边界、安全余量、锁定、选区和明确角色阶段约束继续保留。

## 实测范围

本机三个固定位置的冷评分局部对照约 1.2–1.7 秒，进入模型的合格候选为35–68个；同一乐段连续插入约0.4–0.6秒，每次最终选择仍请求模型。召回结果固定以隔离选镜开销，数据不包含新 embedding、首次音乐理解、浏览器绘制、后期声音／效果与最终导出；跨段、换主题、换服务和排队都会改变延迟。

三个实际局部 A/B 视频经另一多模态模型辅助审片，两处新版更合适、一处相同，主要涉及人物可读性和衔接。它不是人工盲评或整片审美保证，私人原始试验日志未随源码发布。
