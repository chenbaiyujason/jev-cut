# 处理原理

## 离线证据

视频先以原始帧率进行镜头切分，再建立播放器代理与模型分析代理。镜头时间、字幕时间与音频事件都保留对原素材的映射。

TransNetV2 的检测输入是 48×27 RGB，但时间采样仍按原始帧序列。模型分析代理默认约 640 像素宽、12fps、H.264 CRF/CQ 30、单声道 AAC 64kbps；送入理解模型时使用较低采样率。分析块按完整镜头组合，默认约90秒、最多24镜头，并保留上下文。压缩减少上传字节，不保证 token 费用与字节同比下降。

理解结果含人物、动作阶段、景别、方向、情绪、台词含义、声音事件与不确定性。错误镜头ID和越界时间会被拒绝或丢弃。三帧参考图必须取自对应镜头内部；边界安全复核防止一个候选内残留别的切镜。

可选 embedding 把语义文档和图像映射到向量，帮助跨语言与意象查询。字幕也有独立时间证据，不能只因文字相关就忽视画面人物是否正确。

## 创作与决策

音乐理解记录实际听到的节奏、音色、人声与能量变化。规划模型结合音乐和目标提出段落职责、节拍密度及声音意图；它不应凭空宣称某个具体镜头已经存在。

每次填充时间轴时，从当前完整可检索素材中重新召回，再按来源、安全窗口、时长与运动要求生成可执行候选。决策模型结合当前音乐位置、前后文与证据来评分/选择，结果可以与语义相似度首位不同。差异率不是质量提升率。

当前不再按检索排名固定截为16个。全部合格候选先接受独立的基础适配评分，共享主题与乐段前缀；稳定适配可缓存，最后的实际窗口选择始终读取实时上下文。具体约束与计时口径见 [候选选择与缓存](SELECTION.md)。

同一素材插入还可能需要选择原声、重音、转场与调色。代码先确定哪些方案合法，模型再在其中选择，包括“保持现状”。转场需要考虑两边镜头及隐藏源帧，不能只给当前镜头贴效果。

## 工作台与事务

项目时间单位为整数项目帧；源视频入出点使用源帧率。不同帧率下边界拆分要保留取样相位，不能把小数源偏移随意取整而改变范围外画面。

选区外、未选中的间隙和锁定内容不可被隐式改写。复杂动画、跨界声音和转场需要保护或显式处理。局部请求携带 `baseRevision`，过时结果不覆盖新编辑。撤销按一次事务恢复。

渐进生成与选区事务是两类流程：前者允许逐段发布已经排好的真实镜头并在取消时保留已生成前缀；后者在整轮完成前不提交。不能混淆两种取消语义。
