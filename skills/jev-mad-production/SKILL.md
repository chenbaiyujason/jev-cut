# 从素材到首次剪辑

定位 `package.json` 名为 `jev-cut`、含 `tools/doctor.mjs` 的仓库根目录。没有仓库时，克隆 `https://github.com/chenbaiyujason/jev-cut`。以下命令都从仓库根目录执行；当前仍在旧开发目录工作时，使用独立发布副本，不搬走源码或共享其 `.local` 数据。

本 Skill 不自带素材、密钥、理解模型或 jev 推理引擎。先确认用户已有视频/字幕/音乐的位置、理解与 embedding 服务、决策服务，以及本机配置位置。缺失的信息一次说明；不要求用户在聊天里粘贴 Key。不把示例角色、剧集数量或开发模型名当作本次要求。

详细命令、完成条件和故障处理见 [执行手册](references/operations.md)。只读取当前阶段需要的部分。

## 1. 建立可运行环境

1. 检查 Node.js 22.12+（推荐24）、Python 3.12+（验证版本3.13）、FFmpeg/ffprobe 和浏览器。
2. 执行 `npm run setup`，创建媒体 Python 虚拟环境，安装两份 requirements，下载 TransNetV2 权重。
3. 将真实配置写入被忽略的 `apps/backend/localdevenv/.env`。理解、embedding、决策是三个独立角色；embedding 可明确关闭，理解模型和兼容决策服务仍需可用。
4. 运行 `npm run doctor -- --stage environment`。再用 `npm run doctor -- --models` 发送小型纯文本请求检查接口。它不证明多模态可用，下一阶段的 pilot 才会发送真实压缩素材。

不要将启动了网页当作模型环境已配好。切镜和代理可走较慢的 CPU 路径；浏览器预览/导出仍需实际验证图形与编解码支持。本仓库不替用户下载 jev 权重或假装启动了推理服务。

## 2. 准备和检查本地输入

用户只有网址时，使用可用的合法下载入口或下载工具取得真实文件；已有 OpenCLI 可复用，但不是前置依赖。按本次要求区分正片、预告与其他视频。

用 ffprobe 确认视频流、音轨、时长和帧率，记录来源与文件版本。检查损坏、重复文件、字幕是否对应同一版本，抽查开头/中段/末尾对齐。VFR 需要先规范化成明确 CFR 输入并重新检查字幕；不能直接套假定帧率。

按 `examples/sources.example.json` 建立 `data/sources.json`：编号唯一，路径相对清单目录。没有字幕允许继续，但对白证据较弱。清单没有自动字幕偏移字段；有偏移先生成对齐后的字幕文件。

## 3. 先本地处理，再做模型理解

```sh
npm run media -- --manifest data/sources.json --stage local --dry-run
npm run media -- --manifest data/sources.json --stage local
npm run doctor -- --stage local
npm run media -- --stage understand --pilot
```

`--dry-run` 只验证清单与路径，不证明文件可解码。local 阶段包含原帧率切镜、浏览器/分析/剪辑代理、镜头内参考帧、字幕索引和重复片头片尾线索。

抽查镜头边界、三帧是否在镜头内、字幕与音轨是否正确，以及 pilot 的人物/动作/台词理解。参考图不是动作连续性的证明。短镜头、低动作量或安静眼神不自动等于废片；重复 OP/ED 检测是线索，不能盲删剧情。

## 4. 完整理解与建库

小样本通过后：

```sh
npm run media -- --stage understand
npm run media -- --stage embedding
npm run media -- --stage index
npm run doctor -- --stage index
```

如果明确采用文字检索，将 `MAD_EMBEDDING_ENABLED=false` 并跳过 embedding 命令。其余阶段不变。pilot 只产出 `pilot-enriched.json`，不能用它冒充完整 `enriched.json`；完成数量按实际清单判断，不要求11集。

失败只重跑对应阶段，保留成功结果。当前缓存不是自动依赖追踪系统：视频、字幕、字幕偏移、模型或分析参数变更后，先按执行手册明确哪些缓存需要重新建立，不执行“删除整个缓存再试”。索引未通过检查时，不进入自动剪辑。

## 5. 开始剪辑和验证

执行 `npm run dev`，打开输出的工作台地址；端口被占用时使用独立端口，不停止其他项目。导入配乐，在项目菜单选择“从音乐新建剪辑”，输入主角/主题与时长。由真实音乐决定节奏，不要求用户手写每个切点。

也可把“jev匹配”拖入时间轴空位做单镜填充；已有工程用右侧面板按选中片段、入出点或明确范围修改。不要把单镜、选区和重算全片混为一谈。

RAG 提供候选，jev 判断实际素材与剪辑选项；下一次决策仍可搜索全库。原声轨可能包含原配乐，不能标成纯人声。保留源帧、转场余量、锁定、版本校验与撤销；模型结果不能越过这些执行约束。

先完成一段短样片的实际播放/导出检查：人物、动作与视线衔接、第一处节奏释放、源帧误重复、黑屏、台词和原声音量。随后再扩大处理范围或长度。

## 6. 交接

交付可编辑工程、样片、实际决策记录，以及一份本机交接说明：素材清单位置、各阶段状态/数量、模型角色与ID、未解决问题、下一条命令。计时区分离线处理、音乐理解、决策、应用和渲染，不把热缓存或加速录屏称为冷启动实时性能。

源码发布不包含用户原片、字幕、密钥、权重或私人索引；素材和模型另受各自许可约束。
